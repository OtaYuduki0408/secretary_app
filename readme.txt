# Androidフロント 認証アーキテクチャ修正計画

## 1. 現状の問題点

- **認証バイパス**: アプリ起動時にログイン画面を経由せず、直接メイン画面にアクセスできてしまう。
- **ログイン機能不全**: ログイン画面で認証情報を入力しても、ログイン処理が実行されない。
- **セキュリティリスク**: SupabaseのAPIキーがAndroidアプリのソースコード内に直接書き込まれており（ハードコーディング）、漏洩のリスクがある。

## 2. 修正方針（新しいアーキテクチャ）

AndroidフロントからSupabaseへの直接接続を廃止し、セキュリティと保守性を向上させる。
すべての認証リクエストは、既存の **Webフロント（Flaskサーバー）** を経由するアーキテクチャに変更する。

### メリット
- **セキュリティ向上**: APIキーをクライアントアプリから削除できる。
- **ロジックの一元化**: 認証ロジックをWebフロントに集約し、コードの重複を防ぐ。
- **保守性の向上**: クライアントごとの個別実装が不要になる。

## 3. 具体的な修正タスク

### Task 1: Androidフロント (`android_app`) の修正
- **`AuthRepository.kt` の改修**:
    - `signIn`メソッドを、Webフロントのログインエンドポイント（例: `/login`）にHTTPリクエストを送信するよう変更する。
    - Webフロントから返されたセッション情報（トークン等）を`UserSessionStorage`に保存するよう変更する。
- **不要なコードの削除**:
    - `SupabaseConfig.kt`, `SupabaseAuthApi.kt` など、Supabaseへの直接接続に使用していたファイルを削除または整理する。

### Task 2: Webフロント (`secretary_app`) の修正
- **`/login` エンドポイントの改修**:
    - 現在のブラウザからのフォーム送信に加え、AndroidアプリからのJSON形式のリクエストも受け付けられるようにする。
    - ログイン成功時、ユーザー情報やセッション情報をJSON形式でクライアントに返却するよう変更する。

### Task 3: 根本的な問題の修正
- **`MainActivity.kt` の画面遷移ロジック修正**:
    - アプリ起動時に認証状態を**同期的**に、かつ**正確に**チェックする。
    - 認証済みの場合は `main.html` を、未認証の場合は `login.html` を表示するように、画面遷移ロジックを修正する。これにより、認証バイパスの問題を根本的に解決する。
